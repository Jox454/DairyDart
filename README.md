## 2. АРХИТЕКТУРНЫЕ ПРИНЦИПЫ (СТРОГО)

### 2.1. Разделение на слои
- **Domain (Бизнес-логика):** Чистые Dart-классы (Entity, Use Cases, Repository Interfaces). Этот слой НЕ должен зависеть от Flutter, внешних фреймворков или сторонних библиотек.
- **Data (Данные):** Репозитории (Реализация), DTO (Data Transfer Objects), источники данных (Remote/Local Data Sources). Этот слой реализует интерфейсы из Domain. Обязательно реализуй методы-мапперы (или extension) для конвертации DTO из Data-слоя в чистые Entities из Domain-слоя, чтобы UI не работал с сырыми данными из API/БД.
- **Presentation (UI):** Только экраны, виджеты и управление состоянием. Этот слой НЕ содержит бизнес-логику, а только отображает состояние и передает действия пользователя.

### 2.2. State Management (Управление состоянием)
Используй пакет **flutter_bloc** (а именно класс **Cubit**) для реализации подхода MVVM, где Cubit выступает в роли ViewModel. Он должен:
- Принимать вызовы от UI.
- Взаимодействовать со слоем Domain (Use Cases).
- Испускать неизменяемые состояния (States), на которые подписывается UI через BlocBuilder/BlocConsumer.
- Интерфейс должен оставаться «глупым» (не содержать логики).

### 2.3. Внедрение зависимостей (DI)
Используй пакет **get_it** для внедрения зависимостей. Покажи, как зарегистрировать все слои (Data Sources, Репозитории, Use Cases, Cubits) в файле инициализации DI, чтобы код был слабо связанным и тестируемым.

### 2.4. Обработка ошибок
В слое `/core` создай базовые классы для обработки ошибок:
- **Failure** (для Domain-слоя).
- **Exception** (для Data-слоя).
Это позволит системно прокидывать ошибки до интерфейса.

 ПРАВИЛА НАПИСАНИЯ КОДА
❌ СТРОГО ЗАПРЕЩЕНО:
НЕ смешивай бизнес-логику с виджетами. Запрещено писать if (user.isLogged) внутри build() контекста. Для этого есть Cubit/Bloc.

НЕ используй setState() для сложной логики или данных, которые используются на нескольких экранах.

НЕ хардкодь строки и стили. Только через AppStrings или Theme.of(context).

НЕ клади модели данных (Entity) в слой Presentation. Используй DTO для данных и конвертируй их в Domain-сущности через мапперы.

НЕ пиши длинные методы (больше 30-40 строк). Разбивай на мелкие функции.

НЕ используй BuildContext в Domain-слое — это нарушает независимость.

НЕ пиши print() в production-коде. Используй debugPrint() или логирование.

✅ ОБЯЗАТЕЛЬНЫЕ ПРАВИЛА (ХОРОШИЙ ТОН):
Асинхронность: Все IO-операции (запросы к БД, API) должны быть async/await и обернуты в try/catch внутри Cubit/UseCase.

Переиспользование: Выноси повторяющиеся виджеты в отдельные файлы в папку shared/widgets/.

Именование:

Классы: UpperCamelCase (например, DiaryCubit).

Файлы: snake_case (например, diary_cubit.dart).

Переменные и методы: lowerCamelCase.

Комментарии: Пиши комментарии только для сложных бизнес-алгоритмов. Очевидные вещи (геттеры, сеттеры) комментировать не нужно.

Состояния: Используй Equatable для сравнения состояний в Cubit/Bloc, чтобы избежать лишних перестроек виджетов.

Константы: Максимально используй const для виджетов, чтобы уменьшить пересборку (re-build).

Строгое соблюдение порядка импортов:

dart:core

package:flutter

сторонние пакеты (flutter_bloc, get_it, dio)

внутренние импорты (features/, core/)

5. ПРОИЗВОДИТЕЛЬНОСТЬ (ЧТОБЫ ПРИЛОЖЕНИЕ РАБОТАЛО БЫСТРО)
ListView: Для больших списков ОБЯЗАТЕЛЬНО используй ListView.builder.

Image: Используй FadeInImage или cached_network_image для картинок из интернета.

const: Максимально используй const для виджетов.

RepaintBoundary: Оборачивай анимированные или часто перестраиваемые виджеты в RepaintBoundary.

Не создавай виджеты внутри build() без необходимости: Если виджет не зависит от состояния — вынеси его в отдельную переменную или метод.

6. КРОСС-ПЛАТФОРМЕННОСТЬ (ANDROID & iOS)
Плагины: Проверяй поддержку обеих платформ в pub.dev.

Адаптивный дизайн: Используй MediaQuery и LayoutBuilder для адаптации под разные размеры экранов (планшет / телефон).

Навигация: Используй go_router или auto_route для централизованного управления маршрутами.

Разрешения: Убедись, что запрос разрешений работает корректно на обеих платформах (используй permission_handler).
